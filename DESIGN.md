# BatchClip studio UI

## Design read

- **Surface:** Native desktop application UI for a repeated media-production workflow. BatchClip moves a creator from source ingestion through AI processing, clip approval, and rendering.
- **Audience:** A creator or editor working in a resizable Electron window, scanning many vertical clips and switching between quick approval decisions and slower AI/render progress.
- **Single job:** Make the next confident action obvious at every stage: bring in a source, understand the pipeline, approve the best clips, then export them.
- **Task and risk:** Ingestion and review are frequent, time-sensitive decisions. Processing and rendering are slower, failure-prone operations, so honest progress, recovery, and destination details must stay visible.
- **Content:** Source filenames, video thumbnails, clip scores, approval state, stage progress, render destinations, and truthful errors. Values can be long, missing, empty, or partially complete.
- **Platform:** Electron desktop window with mouse, keyboard, drag-and-drop, and resizable layouts. The production window now has a practical 900×640 minimum, with adaptive behavior verified at that split-screen size and a 320px reflow stress contract.
- **Constraints:** Light is the default and dark is an explicit persisted choice. Light uses a warm canvas with white raised surfaces; dark keeps the locked brand seeds: espresso `#23100c`, cream `#f6ecd9`, and violet `#9f75ff`. Existing shadcn/Radix primitives, Lucide icons, Inter font assets, routing, pipeline handlers, and render subscriptions remain the source of truth.

## Evidence and direction

The local application evidence favors stable geometry, compact controls, semantic status colors, and named transitions. The material model is neutral and classic in light mode, while the existing espresso palette remains available for low-light sessions. Linear and Superhuman are aligned references for stable application hierarchy, compact controls, and keyboard-friendly orientation. Intercom is a contrast reference for keeping status and recovery visible, but its heavier workspace chrome is not appropriate here.

## Design thesis

BatchClip is a **quietly cinematic clip studio**: a warm light canvas or deep espresso surface, readable foreground text, violet for action, and named accents for pipeline, media, AI, transcription, face detection, and rendering. The distinctive product device is a static filmstrip rule/grid behind the work surface, paired with an always-present **Source → Shape → Export** stage rail in the draggable header. It grounds the composition in the editorial sequence without competing with real media.

- **First glance:** wordmark, current stage, source status, and the one primary action.
- **Second glance:** current screen title, useful count or progress, and recovery/status details.
- **Primary actions:** choose/drop source, cancel/retry processing, approve/reject/open clip details, render/export.
- **Supporting evidence:** real thumbnails and video previews, source filename, score, stage progress, render destinations, and actual errors.
- **Geometry:** 8px rhythm; 12px cards; 8px controls; pill shapes only for compact statuses and approval chips; shared content edges use a `max-w-6xl` clip workspace and `max-w-3xl` focused stages.
- **Typography:** self-hosted Inter remains the stable UI family. Tighter display tracking and weight carry headings; monospace is reserved for paths, percentages, and token counts.
- **Color roles:** `background` is the warm light canvas or espresso dark surface; `card` is the raised work surface; `muted-foreground` is measured secondary copy; violet is action/focus; `success`, `warning`, `destructive`, `info`, and `signal` cover common states. Source indicators are named: orange for pipeline/media, purple for AI, blue for transcription, yellow for render, cyan for face detection, and red for errors. Each indicator also carries text, an icon, a badge, or native progress semantics.
- **Motion:** the existing 150ms screen transition remains the only spatial transition. Added feedback uses property-specific color, border, opacity, shadow, and progress transitions. Reduced motion removes non-essential movement while preserving immediate state changes.
- **Anti-default check:** no glass cards, ambient loops, fake metrics, emoji, oversized hero, equal feature-tile grid, decorative icon medallions, generic hover lift, or generated em dashes. The filmstrip layer belongs because it directly references video editing and remains static behind content.

## Component states

- **Source intake:** idle, drag-over, browsing, URL/path entry, submitting, invalid source, Python setup required, setup error, recent-project rows, empty recent list.

Every status pairs color with text, icon, or native progress semantics. Async actions retain useful content and expose pending, success, failure, retry, and cancel behavior.

## Recovery continuity (PROJ-04)

- **Single job:** let a creator identify the exact autosave, understand what can return, and choose Restore or a separately confirmed Discard without risking the recovery file.
- **Snapshot identity:** every autosave receives a new id; legacy snapshots receive a stable content hash. Acknowledgement stores only that identity, so a later crash is always checked.
- **Project evidence:** the dialog shows project name, source name, localized autosave time, creator-facing stage, and counts for sources, transcripts, clips, and cut plans.
- **Safe restore:** parsing and state replacement finish before the snapshot is touched. A restored project is marked dirty and immediately receives a new atomic recovery-only snapshot without overwriting its project file; failed restores keep the prior file and remain retryable.
- **Destructive path:** Discard opens a second alert naming the project, autosave time, recoverable counts, and the exact boundary: source media and manually saved projects remain untouched. Failed deletion stays open and keeps the snapshot unacknowledged.
- **States and access:** load failure, restore pending/error, discard pending/error, success, and disabled duplicate submission are explicit. Radix supplies modal focus containment; visual, DOM, and keyboard action order match at narrow and desktop widths.
- **Thesis:** a calm edit-room recovery sheet uses the existing warm/espresso surfaces, violet primary action, Lucide icons, Inter type, and compact editorial metadata. No new visual system or decorative motion was introduced.

## Desktop lifecycle safety (PROJ-05)

- **Single job:** close, quit, and restart only after every project/settings save and processing/export cancellation has explicitly settled.
- **Native flow:** Electron owns the guard rather than an async `beforeunload`. Native dialogs name the project or active stage and keep the safest choice first.
- **Reference adaptation:** EZ Coder's main-owned workspace/relaunch continuity informs the coordination model; BatchClip replaces session language with project names, creator edits, processing stages, exports, and completed media.
- **Concrete choices:** unsaved work offers `Save and Quit/Restart`, `Quit/Restart Without Saving`, and `Cancel`; active work first offers `Keep Running in Background`, `Stop and Quit/Restart`, and `Cancel`.
- **Settlement:** the reusable `useDesktopLifecycle` hook reports live risk, runs renderer-owned saves/cancellation, and sends an explicit completion result. Main stays open on save failure, save cancellation, cancellation timeout, renderer loss, or stale active state.
- **Settings:** closing Settings separately offers `Save Changes`, `Discard Changes`, and `Cancel`. Its Advanced restart action uses the same project/job guard, and the shared restart bridge also covers update-initiated relaunches.
- **Continuity:** stopping processing preserves the source and completed/cached artifacts; stopping an export preserves completed outputs. Keeping work running minimizes the app rather than destroying its renderer.
- **Access:** platform-native message boxes provide keyboard traversal, Escape cancellation, system focus, and screen-reader semantics without introducing a second modal visual system.

## Exact workspace and missing media (PROJ-06 / PROJ-07)

- **Single job:** reopen a content project at the same editorial decision, then recover moved footage without sacrificing transcript, clip, brief, plan, or export evidence.
- **Continuity model:** schema v4 stores the active stage and source, selected clip, review filter and sort, inspector tab, grid scroll, per-clip playhead, Creative Brief, long-form plan, durable render rows, and completed output paths. The last saved project is restored behind a dedicated loading state so the drop screen never flashes first.
- **Reference adaptation:** EZ Coder's exact-session hydrate gate becomes a creator-workspace gate. Stable project artifacts load first; media availability is checked afterward because moved footage must not invalidate editorial decisions.
- **Offline media:** `OfflineMediaPlaceholder` is reused by review cards and the inspector. A Radix recovery dialog names every missing source and offers `Locate`, `Search folder`, `Remove`, and `Keep offline`; folder search rebases exact filename matches in one bounded scan.
- **Safety:** Locate refreshes real metadata while preserving source ids and all derived work. Remove uses a second confirmation naming the source and consequence. Preview, processing, and render controls are blocked only for the offline source; transcript, filters, inspector, brief, plan, and completed outputs remain readable.
- **Access and feedback:** actions use native buttons and Lucide icons, pending labels prevent duplicate submission, destructive copy distinguishes project removal from disk deletion, result counts announce filter changes, and the selected tab uses the existing Radix keyboard model.
- **Responsive result:** the relink dialog keeps one aligned card and both recovery paths visible at 1440×960 and the supported 900×800 practical minimum. Long paths truncate with a native title while the source name and every action remain visible.

## Editorial history and render trust (EDIT-01 / EDIT-02)

- **Single job:** let creators move fast through review and refinement while every reversible decision remains visible, reachable, and correctly scoped.
- **Reference adaptation:** EZ Coder's root-level, navigation-independent keyboard QoL becomes standard desktop editing commands. BatchClip routes history to the open clip inspector and otherwise to project-level review and bulk history.
- **Reusable control:** `HistoryControls` supplies the same action-specific labels, Lucide icons, disabled states, focus treatment, and shortcuts in the review toolbar and clip inspector.
- **Native contract:** the Edit menu mirrors the active history label and availability; its displayed accelerators defer to the renderer so text inputs keep native undo behavior.
- **Feedback:** every completed command announces a brief creator-facing result such as `Hook change undone`, `Approval restored`, or `Bulk rejection restored` through the existing accessible toast surface.
- **Render trust:** `Render All` passes explicit ids for one batch. Pending, approved, and rejected statuses remain unchanged, and the rejected-clip confirmation states that boundary before expensive work begins.

## Connections and AI cost trust (CONN-01 / USAGE-01 / USAGE-02)

- **Single job:** prove content-service readiness before a long analysis, then let creators audit what successful AI calls used and how the estimate was calculated.
- **Reference adaptation:** EZ Coder's provider hub and title usage meter become a creator-facing Connections panel plus one compact utility popover. Provider internals stay out of the creative workspace.
- **Reusable connection anatomy:** `ConnectionCard` keeps provider name, encrypted key field, test action, explicit status, recovery feedback, and feature impact aligned across Gemini, Pexels, and fal.ai.
- **Complete states:** encrypted-key hydration shows `Checking configuration`, empty services show `Not configured`, entered keys show `Configured, not tested`, checks show `Testing`, and outcomes show `Connected`, `Connected, degraded`, `Invalid`, `Test failed`, or `Optional and unavailable`. Editing a tested value resets the claim immediately.
- **Graceful degradation:** Gemini names the AI editing features that stop while local transcription, manual review, and rendering remain safe. Pexels names stock B-roll as the only loss. fal.ai is honestly unavailable in this build and does not solicit a new key.
- **Usage bridge:** one root hook subscribes the preload event and updates session totals, capped call history, per-feature aggregates, and per-model aggregates in Zustand. Cleanup removes the listener on renderer teardown.
- **Auditable estimates:** the shared ledger lists exact model ids, paid-tier input/output rates, source URL, version `google-gemini-api-2026-07-17`, and checked date. Provider-reported thinking tokens are included because Gemini bills them as output.
- **Unknown and free-tier truth:** unlisted model calls are excluded rather than assigned another model's rate; partial/unavailable estimates are labeled. The popover says free-tier calls may cost zero and the provider bill is final.
- **Access and adaptation:** native inputs/buttons and Radix menu behavior preserve labels, keyboard focus, pending/duplicate-action protection, async status announcements, narrow card stacking, and reduced-motion progress feedback.

## Informed local-tool setup (SETUP-01)

- **Single job:** let a creator understand and deliberately start the one-time local speech-model install, then recover without reselecting footage or risking project files.
- **Reference adaptation:** EZ Coder's calm prerequisite behavior becomes a creator-facing setup surface. It states the missing capability, keeps technical detail subordinate, uses one explicit action, and preserves the selected video while work completes.
- **Informed action:** the preflight names the 2–3 GB download, typical 10–30 minute duration, exact app-managed storage path, 6 GB free-space requirement, measured free space, required connection, and the boundary between offline local tools and internet-dependent Gemini/YouTube features. Readiness checks never start a download.
- **Complete flow:** checking, ready-to-start, offline, low disk, installing by stage, overall progress, cancelling, canceled, failed, retry, ready, incomplete/repair, and Settings repair use the shared `PythonSetupCard` and one root `usePythonSetup` controller per renderer window.
- **Continuity:** a source chosen during the readiness race is added to the project, named in the setup card, and starts automatically only after setup succeeds. Cancel and failure retain the source and completed download artifacts.
- **Local model contract:** setup now downloads `nvidia/parakeet-tdt-0.6b-v3` into the app-managed model cache and stamps the requirements plus model contract only after verification. Runtime transcription points to the same cache, preventing the first transcription from triggering a surprise model download.
- **Repair and safety:** Advanced Settings exposes `Repair content tools`; retry is idempotent, setup cancellation terminates tracked downloads and child processes, and media IPC handlers fail with the setup/repair action instead of installing invisibly.
- **Responsive and access:** native buttons and progress semantics keep focus/status behavior predictable; Lucide icons pair with text; the action stays visible at 390×844 after the narrow revision; 900px and desktop layouts preserve the same content order without decorative motion.

## Adaptive desktop windows and native menu (WIN-01 / WIN-02)

- **Single job:** keep source intake, progress, clip decisions, and export controls usable in a split-screen production window while standard desktop commands stay reachable from the OS menu.
- **Native window contract:** the main window defaults to 1180×760 and can shrink to 900×640; Settings can shrink to 400×480. Every stage keeps its primary action visible and its content region scrollable at 900×640.
- **Platform chrome:** macOS keeps the hidden-inset title bar and traffic-light clearance; Windows keeps native titlebar controls and a visible menu bar. The settings window uses native chrome on both platforms and remains explicitly resizable/maximizable.
- **Native menu:** File exposes New Project, Open, dynamic Open Recent, Save, and Save As. Edit mirrors active Undo/Redo labels. View exposes platform zoom/full-screen roles. Settings, Keyboard Shortcuts, What’s New, Check for Updates, and About move to platform-standard menu locations and accelerators. New Project protects dirty or active work, while signed updates check quietly and surface progress only when a release is available or the creator asks.
- **Reference adaptation:** EZ Coder's small-window resilience and dense desktop shortcuts were adapted to creator tasks, while BatchClip keeps its editorial stage rail, media-first review, and calm cut-room visual language.

## Transparent background processing (PROCESS-01 through PROCESS-08)

- **Single job:** let a creator verify that real media is moving through transcript, moment, story, face, timing, and styling stages while completed evidence remains useful after navigation, cancellation, failure, or restart.
- **Reference adaptation:** EZ Coder's `ActivityBar` contributes stable elapsed/status geometry and explicit cancellation; `LiveToolPanel` contributes a rolling three-row feed, collapse/detail behavior, and settled results. - **Real source:** `SourceMediaSummary` shows the saved poster frame, duration, source dimensions, locked output dimensions, a compact real filmstrip, and an FFmpeg-derived audio waveform. Missing poster/waveform states remain neutral and truthful.
- **Activity and proof:** `ProcessingActivityFeed` shows the latest three meaningful creator operations by default and expands to retained detail. - **Honest timing:** every active stage keeps elapsed and ETA geometry reserved. - **Durable model:** `CreatorJob` records project/source identity, stage, progress, timestamps, cached source path, completed stages, activity, proof, failure state, and outputs outside the mounted processing screen. - **Background control:** `JobsHud` is mounted in `StudioHeader` on every stage and the lobby. - **Native feedback:** the main process mirrors work through `BrowserWindow.setProgressBar`; native notifications cover ready clips, completed exports, and action-required failures. Clicking a notification restores/focuses the window and routes to its durable job. The existing notification preference is now visible in Settings.
- **Preservation:** the primary action is `Stop and keep progress`. Source, transcript, clips, cached media, completed proof, and stage checkpoint remain. `Start over and discard cache` sits behind a named destructive confirmation and leaves the source video on disk.
- **Reusable components:** `SourceMediaSummary`, `ProcessingActivityFeed`, `JobsHud`, `CreatorJob`, job progress/ETA helpers, and root `useNativeJobIntegration` separate media evidence, activity behavior, global control, durability, and native effects.
- **Access and motion:** native buttons, lists, progress semantics, status announcements, Lucide icons, visible labels, stable geometry, named color/border/opacity transitions, and the existing reduced-motion rule remain the contract. No tool names, emoji UI, ambient motion, hover lift, glass treatment, fake metrics, or generated em dashes were added.
- **Responsive behavior:** the processing card uses media/evidence plus stage columns from 820px and stacks in DOM order below it. Both columns live in the existing scroll region; the narrow source column repeats the same `Work in background` and `Stop and keep progress` actions before the activity feed, so the primary controls remain visible at 390×844.
