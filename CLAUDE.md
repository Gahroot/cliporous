# BatchClip (`batchclip`, dir `cliporous`)

Read CONTEXT.md before naming anything.

Electron desktop app: long-form video → AI-scored short-form clips with burned-in captions. Hybrid render: FFmpeg (encode/crop/overlay/concat) + Remotion (alpha-channel compositions composited by FFmpeg). Primary path is 9:16 vertical; an additive 16:9 "longform" path also exists.

> Product naming is inconsistent across layers: package `batchclip` / appId `com.batchclip.app`, but window title and temp prefixes use `BatchContent`/`batchcontent-`, and the renderer wordmark reads "BatchClip". Don't "fix" this without checking.

## Stack

Electron 34 + electron-vite 5 + electron-builder 25 · React 19 + Radix/shadcn + Tailwind 3.4 + framer-motion · Zustand 5 (+ immer, sliced) · @google/genai (Gemini) · Remotion 4 (ProRes 4444 + alpha) · ffmpeg-static + @ffprobe-installer · better-sqlite3 · TypeScript 5.7 strict · Vitest 4 · Biome 2. npm (package-lock.json). **Node >= 22 required.**

Python sidecar (`python/`, set up via `npm run setup:python`): `transcribe.py` (NeMo Parakeet TDT v3 ASR), `face_detect.py` (PySceneDetect + MediaPipe → 9:16 crop timelines), `download.py` (yt-dlp). All emit newline-delimited JSON on stdout (`{type: progress|done|error}`). Bridge in `src/main/python.ts`; first-run bootstrap in `python-setup.ts`. Windows keeps its own venv at `%APPDATA%/batchcontent/python-env/` — never copy a mac/Linux `python/venv/` to Windows.

## Commands

```bash
npm run dev            # electron-vite hot-reload
npm run build          # electron-vite build (does NOT typecheck)
npm run typecheck      # tsc -b --noEmit
npm run check          # biome check (lint + format)
npm test               # vitest main config then renderer config (sequential)
npm run test:main      # main-process tests (node env)
npm run test:renderer  # renderer tests (jsdom)
npm run verify         # check + typecheck + test  (the full gate)
npm run setup:python   # bootstrap python/venv
npm run deploy         # scripts/deploy-windows.sh (replaces whole Windows folder; --fast --yes via deploy:fast)
npm run deploy:mac     # scripts/deploy-mac.sh
```

`npm run build` bundles but skips typing — run `typecheck` separately. Biome is the lint/format gate (`biome.json`). `tsc -b` builds the root solution, which references **only** `tsconfig.node.json` (main/preload/shared) + `tsconfig.web.json` (renderer) — `tsconfig.remotion.json` is standalone and NOT covered by `npm run typecheck`.

## Locked invariants

- **Output:** vertical hard-locked to **1080×1920 @ 30fps** (`OUTPUT_WIDTH/HEIGHT/FPS` in `src/main/aspect-ratios.ts`); only `'9:16'` is configured and `getCanvasDimensions` ignores its arg. Longform path uses `LANDSCAPE_* = 1920×1080 @ 30`.
- **Theme modes.** Light is the default persisted renderer theme with a warm canvas and white raised surfaces; dark is explicit and preserves the brand seeds: espresso `#23100c`, cream `#f6ecd9`, violet accent/primary/ring `#9f75ff`. `src/renderer/index.html` and the native window use the light default to avoid a launch flash; `useTheme.ts` applies the saved mode before React renders.
- **Captions — four modes, one builder** (`src/main/captions.ts`, emits ASS burned via libass): `standard` (white on all words), `emphasis` (emphasis words recolored to accent), `emphasis_highlight` (recolor + display-font swap), `editorial` (renderer default for new settings: `Instrument Serif` sentence case on its own `Editorial` ASS style, per-word timed events — a soft rounded `\p1` pill on layer 0 behind the spoken word, upcoming words dimmed to ~45%, emphasis words italic + accent; pill x-offsets come from embedded Instrument Serif advance widths). Fonts: `Inter` default, `Bebas Neue` display, `Instrument Serif` Regular+Italic; `fullscreen-quote` archetype overrides to italic `Instrument Serif` hero in every mode. Optional `layoutWindows` move the anchor (`stack` below the seam, `stack-flipped` above it, `takeover` at 78%, `pip` at 68% above the speaker window). Accent comes from the selected palette (`settings.longformPaletteId` — now drives short-form too); fallback `#9f75ff`. Many `CaptionStyleInput` fields are tolerated-but-ignored V1 back-compat.
- **Edit styles** (`src/main/edit-styles/`): `prestyj` is `DEFAULT_EDIT_STYLE_ID` and the only short-form (9:16) style; `hormozi` exists **only** for the 16:9 longform path. No multi-style picker for vertical.
- **Short-form graphics must add depth, not repeat speech.** No decorative `statement` scenes or optional fullscreen emphasis quotes in 9:16. Reject them in planning and ignore them in saved/precomputed plans at export; legacy `fullscreen-quote` segments render as the speaker with ordinary captions. Preserve source timing, useful diagrams, attributed-source `quote` scenes and the separate longform behavior.

## Architecture notes

- **Screen flow:** `selectScreen(stage, hasActiveSource)` in `store/selectors.ts` routes 4 screens (drop · processing · clips · render). `App.tsx` wraps each in one `ScreenFrame` (150ms fade + 8px shift) — that is the entire animation budget. Settings is a separate BrowserWindow (`window.api.openSettingsWindow()`).
- **Render pipeline** (`src/main/render/pipeline.ts`): per clip, each `RenderFeature` (`features/*.feature.ts`) runs `prepare → videoFilter → overlayPass → postProcess`. Registered order: `filler-removal, accent-color, word-emphasis, captions, hook-title, rehook, auto-zoom, broll, shot-transition, hyperframes-overlay`. `blocks` and `phrase-emphasis` features exist but are NOT registered (dead). `segment-render.ts` checks `remotion/registry.ts` first (renders ProRes+alpha, FFmpeg composites) else falls back to pure FFmpeg. Encoder pref `h264_nvenc → h264_qsv → libx264` (`getEncoder()` in `ffmpeg.ts`). Per-clip errors isolated; `cancelRender()` SIGTERMs tracked FFmpeg procs.
- **Explainer scenes** (v3): transcript-driven animated diagrams. Planner `src/main/ai/explainer-scenes.ts` (Gemini 3.8 Flash, word-indexed, second review pass, `explainer/variety.ts` rules incl. max two same-`family` scenes in a row) with one spec per kind in `src/main/ai/explainer/kinds-*.ts` (parse untrusted JSON → absolute beat times, layouts, SFX cues; each spec also has `family`, transcript `triggers`, optional `general`/`avoid`). 49 base kinds: v2 (checklist, versus, stamp, flow, stack, statement, number, timeline, notes, question, before-after, chart, chat, network, loop, myth-fact, funnel, hero) + v3 2D (equation, quadrant, venn, definition, study, pictogram, ranking, receipt, streak, spectrum, quote, headline, journey, search, code) + v3 3D (iceberg, balance, podium, compound, dominoes, stairs) + causal systems (bottleneck, momentum, leverage, resource-leak, feedback-control, keystone, switchyard, synchronization, relay, exploded-view). **Shortlist** (`explainer/shortlist.ts`): per clip, code scores kinds/props by trigger hits and the prompt lists only ≤16 kinds and ≤10 hero props (the parser still accepts any valid kind); eval set in `shortlist.test.ts` — add a case when adding a kind. Validator rejection reasons (`ParseContext.issues`) are fed into the review pass. Hero props (71): data/triggers/impact timing in `compositions/explainer/hero-catalog.ts` (React-free, shared with the planner), models in `hero-props/*.tsx` registered in `HERO_PROP_DEFS` (`HeroProps.tsx`), shared clay kit `hero-kit.tsx`; `tone: 'down'` = reversed action (battery drains, lock opens). Visual check: `node scripts/explainer-stills/render.mjs <fixtures.json> [filter]` renders PNG stills + contact sheets to `$TMPDIR/explainer-stills/` (fixtures in `scripts/explainer-stills/fixtures/`; ANGLE GL for 3D). Compositions in `src/main/remotion/compositions/explainer/`: every scene draws on a 1080×960 virtual stage; `SceneFrame` places it per layout (`stack`, `stack-flipped`, `takeover`, `pip`, `over`); chained scenes render as ONE `ExplainerSequence` via `@remotion/transitions`. Colours only via `useStage()` (palette derived in `palette.ts`); motion only frame-driven (`motion.tsx`, `Stage3D.tsx` — never clock-based drei helpers). Beat-time convention: fields named `at`/`…At` are seconds (see `types.ts`). Shorts: `render/explainer-scenes.ts` splices groups into segments (layouts composited in `layouts/segment-layouts.ts`); long-form: `render/explainer-longform.ts` (`over`/`takeover` only, speaker ranges only). Beat SFX: `render/scene-sfx.ts` + `resources/sfx/scene/` (CC0, low-passed, no bright/meme sounds), mixed post-concat. Dev note: dev resolves ffmpeg from the npm `ffmpeg-static` build first (has libass; Homebrew's ffmpeg doesn't, which silently drops captions/hook titles), then PATH. `@remotion/bundler` is a devDependency kept external in `electron.vite.config.ts` (inlining breaks `@rspack/binding`). Face tracking (`python/face_model.py`) uses MediaPipe Tasks with a hash-pinned BlazeFace model downloaded once to the model cache; only MediaPipe results (`faces_reliable`) place floating `over` cards, else they fall back to `stack`.
- **Motion/icon kit:** `motion-tokens.ts` defines weight presets, seekable follow-through, stagger, and bounded overlapping reactions. `graphic-accents.tsx` provides mask-rise scene text, drawn annotations and impact rings (not captions). AI annotations are allowlisted on hero/statement labels, exclusive with later stamps, non-adjacent, with at most one reaction. `hero-props/icon-shapes.ts` contains 12 project-authored filled silhouettes; `icons.tsx` extrudes them. No arbitrary SVG/XML or remote assets. Shared Clay has restrained clearcoat; `StudioEnvironment.tsx` generates a small offline environment without changing the alpha background. Fixtures: `motion-upgrade.json`; after `npm run build`, `node scripts/explainer-stills/verify-motion.mjs` checks repeated-frame equality and ProRes 4444 alpha.
- **Causal motion library:** `explainer/mechanisms/` owns bounded, pure frame-seekable poses, contact paths, shared camera anchors and authored assemblies; `MechanismStage` keeps one WebGL canvas. Semantic carriers are mandatory: rail carts on tracks, parcels on conveyors, recognizable weights/parts (not anonymous cubes). `relay` has six presets: unlock, nurture, attract-process, power-insight, complete-system, idea-process-result. `exploded-view` only accepts mechanism/parcel/gadget templates and their named targets. Causal scene windows never snap inward across setup/final-hold beats. `editorial/` supplies ten opt-in treatment families; `ai/explainer/editorial-contract.ts` grounds optional labels/measurements/numbers in source words and omits invalid extras with diagnostics. No generic stamps/emphasis are auto-injected into causal scenes. Verification: `scripts/explainer-stills/coverage.mjs`, `verify-motion.mjs`, `verify-systems.mjs`, `verify-systems-e2e.mjs`; temporary PNG/video reports stay outside git. `--software-raster` is an explicit POSIX verification override for Chromium alpha-edge rounding, not a production default or cross-GPU guarantee. See `docs/plans/causal-motion-library-verification.md` for measured evidence and limits.
- **Clay explanation expansion:** `explainer/spatial/` supplies eight kinds (house-cutaway, house-build, house-renovation, property-access, neighborhood, floorplan-fit, house-options, property-lifecycle); `explainer/cognition/` supplies six (agent-team, agent-plan, agent-budget, model-training, model-evaluation, evidence-conflict). Their 29 presets reuse `Clay`, the existing studio and one `ExplanationStage`; contractor-crew reuses `HouseModel`. `explanation-layout.ts` reserves model/text regions with projection regression tests. Planner specs/contracts are `ai/explainer/kinds-spatial.ts`, `spatial-contract.ts`, `kinds-cognition.ts`, `cognition-contract.ts`: five source-word-indexed beats, bounded source labels, explicit relationship/condition evidence, no invented winners/profit/grants or arbitrary geometry. Full-window protection also applies to these non-causal stories. Fixtures: `clay-spatial.json`, `clay-cognition.json`, `clay-continuity.json`; real sequence proof: `node scripts/explainer-stills/render-clay-continuity.mjs --media` after building. Shared house identity is not arbitrary cross-scene state morphing. See `docs/plans/clay-explanation-expansion.md` and `clay-explanation-verification.md` for scope and measured limits.
- **Clay concept library:** `explainer/concepts/` adds 18 kinds / 42 presets across information, inference, business-operations, business-populations, perspective and adaptive packs. Reuse `Clay` + `ExplanationStage` and the existing studio; poses are pure and frame-seekable. `ai/explainer/kinds-concept-*.ts` and `concept-*-contract.ts` enforce actor-bound source evidence, finite quantities, explicit conditions, unresolved/simulated states and five-beat windows. `CONCEPT_SCENE_KINDS` joins the existing full-window/no-auto-emphasis protection. Fixtures: `concept-*.json`; shared `concepts/fixture-words.ts` places speech inside the planner's 0.25s lead-in / 0.35s tail. `render/concept-library.test.ts` checks all 42 raw payloads through the real planner, shortlist, rebasing and both render routes. `concepts/mesh-budget.test.ts` checks authored mesh ceilings (not measured GPU/RSS); `scripts/explainer-stills/concept-stress-fixtures.mjs` generates maximum-label, layout-only probes for all 18 kinds. Use `snapshot-bundle.mjs` before parallel render proofs so a later build cannot replace their inputs. After building, `node scripts/explainer-stills/verify-systems-e2e.mjs --concepts` verifies a mixed production export; `--unit` is planner/pipeline-only. See `docs/plans/clay-explanation-vision.md` and `clay-explanation-vision-verification.md` for scope, evidence and limits.
- **Detroit + hybrid explanations:** `explainer/diagrams/`, `detroit/`, `finance/`, `business-systems/` and `ai-systems/` add seven kinds / fifteen presets: detroit-place, fund-flow, ownership-change, portfolio-exposure, cash-timing, token-attention, inference-tradeoff. `visualMode: 'diagram' | 'hybrid'` gives 2D equal standing without a settings migration: identical validated facts/IDs/beats, zero WebGL stages for diagram and one for hybrid. Reuse the existing clay/studio and frame-driven motion. `HYBRID_SCENE_KINDS` joins full-window/no-auto-extras protection; shortlist/coverage limits stay unchanged. Contracts in `ai/explainer/` bind local source evidence, exact minor-unit money, share denominators, unknown states and comparable task metrics; attention is illustrative, never fake telemetry. Seven local landmark pairs are enabled; **Spirit of Detroit remains rights-blocked and absent from the runtime allowlist**. RenCen uses a cylindrical hotel, four faceted offices with slim circular cores and two lower rectangular towers; facades are batched, not per-window meshes. Fixtures: `detroit-landmarks.json`, `hybrid-{finance,business,ai,showcase}.json`; raw production-path tests: `render/hybrid-library.test.ts`. After building and snapshotting, use `render-hybrid-showcase.mjs --bundle <pin> --media` and `verify-systems-e2e.mjs --hybrid --bundle <pin>` (add `--unit` for no-media checks). The optional local pin retains source/hash gates. Showcase cuts do not change production transitions. See `docs/plans/detroit-hybrid-explanation-verification.md`, `docs/asset-provenance/detroit-landmarks.md` and the scoped `COMPLIANCE.md` for actual evidence, baseline failures and rights limits.
- **Long-form scene canvas** (`render/longform-scene-canvas.ts`, `remotion/compositions/scene-canvas/`): at export, runs of 2–5 consecutive approved base-kind scenes in one planning section (gap ≤ 24 s, span ≤ 90 s, ≤ 2 WebGL kinds) render as ONE `SceneCanvas` full-frame segment. Each scene's real `SceneBody` (incl. clay 3D) sits in a sketched panel on a moving whiteboard. The camera leads into each beat, rests with seeded handheld drift and pulls back to show the accumulated story (camera grammar after MIT GG Motion). Panels never freeze: past their last beat they keep a seekable idle layer (`scene-canvas/idle.ts`: float, tilt, 3D orbit via `SceneOrbitContext`, periodic pulse). Approved phrases spoken inside a canvas become board notes (handwriting/ring/sticky) instead of speaker overlays; notes take the first free slot so none covers another note or a panel. Whenever nothing new is drawn for ≥1.2 s the board dissolves to the live speaker (via the story overview when there is time) and returns 0.5 s before the next drawing; a phrase starting in the canvas tail stays an overlay and closes the board first (`closeBySec`). Pure grouping, no AI call and no plan rewrite; `plan.sceneCanvas === false` opts out (absent = on; review-screen switch). Protected causal/concept/hybrid/business kinds stay standalone. On a canvas failure its member scenes render separately (the proof test fails on that fallback). Media proof: `npx vitest run --config scripts/explainer-stills/vitest.scene-canvas.config.ts` with `SCENE_CANVAS_PROJECT/_BUNDLE/_OUT/_START/_END/_STYLE`.
- **Hyperframes** (`src/main/hyperframes/`): animated HTML overlay widgets (`catalog/*.html` + `presets.json`) rendered and composited as a render feature.

## Conventions (project-specific overrides)

- `src/main/index.ts` is bootstrap only — **never** add IPC handlers there. Handlers live in `src/main/ipc/<domain>-handlers.ts` exporting `registerXxxHandlers()`, wrapped with `wrapHandler()` from `ipc-error-handler.ts`. Channel names only via the `Ch` object in `src/shared/ipc-channels.ts` — never hard-code strings. Keep `src/preload/index.ts` and `index.d.ts` in sync.
- AI modules in `src/main/ai/` must reuse `gemini-client.ts` (model chains in `MODELS`; Gemini 3 ignores sub-1.0 temperature — use `thinking` instead). Renderer state in `src/renderer/src/store/` slices (`store.ts` is a re-export shim). shadcn primitives in `components/ui/` are generated — don't hand-edit.
- Path aliases: `@/` → `src/renderer/src/` (renderer only), `@shared/` → `src/shared/`. Tests co-located `*.test.ts(x)`; main tests use `src/main/test-setup.ts`.
- Working dir is macOS; deploy target is Windows via WSL2. Windows logs: `%APPDATA%/batchcontent/logs/`.
